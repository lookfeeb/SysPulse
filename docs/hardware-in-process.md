# 同进程硬件模块与接口采集

生产调用链：Tauri/Rust → HwClient 有界工作队列 → 专用线程 → hostfxr → InProcessBridge.Call → 缓存快照或风扇控制。前端与 Rust 的 Tauri 命令/事件继续保留。

## 运行时与 ABI

- build-helper.ps1 打包 hw-helper.dll、依赖、hostfxr.dll 和私有 shared/Microsoft.NETCore.App 运行时，终端用户无需额外安装 .NET。
- UnmanagedCallersOnly / Cdecl 入口，版本为 1，参数是操作编号、UTF-8 风扇 ID、PWM 和调用方的输出缓冲区，不传递托管对象引用。
- 操作 0 启动、1 快照、2 手动风扇、3 单风扇恢复、4 全部恢复、5 关闭。结果 0 成功、1 缓冲不足、负数表示 UTF-8 错误；只有快照允许扩大缓冲后重试。
- 新快照以 SPW2 开头，在接口记录后增加可选 USB 拓扑及能力来源；Rust 同时兼容 SPW1，旧记录不带这些字段。原生调用入口版本仍为 1。字段为小端、u32 UTF-8 长度、单字节存在标记、64 位计数。Rust 最多接受 4 MiB / 16384 项数组，拒绝截断、非有限数字、无效 UTF-8、标记和尾部垃圾；USB 合并组最多 256 条逻辑记录。
- 16 项队列、3 秒调用截止时间、30 秒初始化截止时间。取消/过期的排队控制不执行；已进入驱动的控制不能取消，迟到结果尝试恢复 BIOS 控制。
- CLR 常驻至进程退出；不在驱动线程存活时卸载，不启动替代采集器覆盖旧实例。原生故障可能影响整个应用，驱动挂起不能安全强杀。
- 普通传感器 1 秒、磁盘 3 秒、接口 5 秒，年龄独立；接口超过 15 秒停止显示旧连接状态。
- Program.cs 和 JSON 协议保留为独立诊断/历史基准入口，生产 Rust 不调用它。

## 数据含义

| 来源 | 数据 | 限制 |
| --- | --- | --- |
| SMBIOS Type 8 | 连接器名称、类型 | 没有实时插拔状态，不从名称猜速率 |
| SMBIOS Type 9 | 插槽、宽度、明确报告的 PCIe 代际、开机占用 | 固件可能缺失或保留占位信息；M.2 不等于 NVMe |
| USB Hub IOCTL | 伴随端口组、状态、协议通道、协商速率、Type-C、VID/PID | 包含扩展集线器；仅合并双向确认的伴随关系；USB 3.x 协议位不能区分物理插孔的 5/10/20 Gb/s 上限 |
| USB BOS / Device Qualifier | 已连接设备的 USB 能力及来源 | 与物理插孔能力分开；SSP 属性只证明每通道速率，最小通道数不能当作最大通道数 |
| Windows PCI 属性 | 设备最大/当前链路速率及宽度 | 设备能力不等于插槽上限；多功能设备可有多条记录 |
| Windows 网络接口 | 连接状态及当前链路速率 | 不从协商速率推测最高速率；包含扩展或虚拟适配器 |

PCIe 保留 GT/s 和通道宽度，例如 8 GT/s ×16，不当成应用有效吞吐。固件“已占用”与 USB“已连接”分别显示来源。SATA、显示输出等接口没有可核实的实时数据时保持未知，不虚构每个物理插孔的状态。

依据 Windows SDK usbioctl.h、usbiodef.h、pciprop.h 和 SMBIOS DSP0134 Type 2/8/9。接口读取均为只读查询。

## 通用接口列表

界面直接以列表显示当前电脑自动采集的接口，不保留按型号定制的规格目录、官方资料链接或规格/实时视图切换。所有主板都使用相同的 SMBIOS、USB Hub IOCTL、Windows PCI 属性和网络接口采集流程，主板型号不参与预设数据匹配。

列表显示接口名称、形态、协议/类型、协商速率、系统报告的能力、连接状态和来源；保留接口分类与分页，不提供搜索框、USB 形态/版本下拉框或“仅已连接”勾选框。“当前已连接”数量是绿色筛选按钮，带筛选图标；选中后变为深绿底白字和勾选图标，再次点击取消。它与当前接口分类组合筛选，切换时回到第一页；其余顶部数量仅展示。

热插拔采用周期采集：USB、PCIe 和网卡约每 5 秒重新枚举，随后随快照传到界面。没有设备事件即时通知，因此不是零延迟，更新还受到设备枚举和驱动耗时影响。固件接口清单与插槽占用仅在启动时读取，不作为实时热插拔状态。

USB_GET_PORT_CONNECTOR_PROPERTIES 提供伴随端口路径和索引，只有双方互相确认才合并；组内任一通道连接就显示已连接。断开后清空协商速率与设备能力。合并组仍可能是内部通道或扩展集线器，不等于机箱插孔。

“系统 USB 通道上限”只在全部通道协议已知、伴随映射完整且仅支持 USB 1/2 时显示 12/480 Mb/s，含 USB 3 或映射不完整就不推算。前端也忽略缺少来源的旧 helper 上限值。设备描述符能力单列为“设备 USB 能力”；未可靠获取的上限行隐藏。PCIe 单独标注“设备链路上限”。

支持 USB_GET_NODE_CONNECTION_SUPERSPEEDPLUS_INFORMATION 的驱动可报告当前每方向 lane 速率与通道数，据此得到当前 10/20 Gb/s 等协商速率；驱动未返回则保留粗粒度状态。BOS 的 SuperSpeed 支持位图提供设备能力，SuperSpeedPlus 则按每通道展示；不从 bcdUSB 版本、Type-C 形态或已连接设备速度推测物理口上限，也不把共享 transport 的 MaxPotentialBandwidth 分摊到单个插孔。当前尚不能可靠自动读取本机空闲 USB 3 插孔的最高 10/20 Gb/s 设计能力。

## 本次验证

命令见 [验证说明](../tests/hw-helper/README.md)。本机 MSI MPG Z790 EDGE WIFI 的 49 条 USB 逻辑记录合并为 32 组，其中 3 组被系统标为 Type-C；另有 22 条固件连接器、7 条固件插槽、5 条 PCIe 设备链路、6 条网卡，合计 72 条列表记录。型号仅用于记录验证环境，不参与采集匹配。独立只读 USB 采集两次分别为 29.78 / 33.74 ms，不是完整硬件采样耗时或性能保证。

前期 500 次串行缓存调用（含调度、ABI 编码/复制、Rust 解码）一次复验 p50 0.0968 ms、p95 0.1199 ms；另两轮 p50 分别为 0.1218 ms、0.1772 ms。接口展示修正期间的并行构建负载下复验为 p50 2.6361 ms、p95 8.0625 ms。数据受主机负载影响，旧版没有接口清单，不能声称固定提速比例、总内存下降或纳秒级硬件响应。

本次 C# 41 项通过，包含 BOS/SSP 描述符边界、双向伴随合并、缺失协议不可推断上限、USB 2 双速描述符验证。Rust 常规测试 165 项通过、4 项按需测试跳过，包含 C# SPW2 fixture 解码、SPW1 兼容、无效元数据拒绝。前端相关 14 项通过，生产前端构建和隔离 UI 类型检查通过；helper 已重新打包。

新版 SPW2 的同进程生命周期和完整工作线程实机测试均通过，实际输出包含 USB 能力来源与合并元数据。此次 1000 次原生缓存读取 p50 44.6 µs / p95 58.5 µs，500 次含工作队列和 Rust 解码的缓存读取 p50 122.7 µs / p95 176.5 µs；这些是缓存路径，不能解释成硬件采样达到该响应速度。

新版界面以实际快照回放确认 72 条记录、32 组 USB、3 组 Type-C，能力来源和协商速率分列，未知上限行隐藏。USB 类别与绿色连接筛选组合后为 11 条，第二页为 1 条；模拟全部 USB 断开后正确进入空结果并移除设备信息。642px 窗口无整页横向溢出，接口列表内部滚动。

尚未做真实插拔、风扇写入、长时压力、ARM64 实机或 NSIS 安装验证。通用列表已用实机快照回放核对分页、数据缩减时页码钳制、来源和速率标签；另用模拟型号确认没有型号定制分支。本次移除筛选行后，已确认没有下拉框、复选框或顶部隐藏筛选，模拟连接/断开状态和设备信息随快照更新，类别空结果可返回全部列表。没有卡片、搜索框或官方资料按钮。之前 640 / 800 / 1100 宽度验收没有整页横向溢出，窄窗口通过列表内部横向滚动保留完整列。截图工具此前超时，界面未完成像素级截图验收。
